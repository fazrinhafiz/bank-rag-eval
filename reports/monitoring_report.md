# Monitoring report: simulated drift on real customer queries

Generated by `python scripts/simulate_drift.py`. Every request is a real customer query from Banking77 or a real
injection attempt from deepset/prompt-injections, run through the real pipeline (retrieval mode `tfidf`, threshold 0.2813). Only the traffic mix and the surge are simulated, with fixed seeds.
Baseline mix: 85% in-scope intents (covered or partly covered), 13% uncovered intents, 2% English injection attempts. The drifted window adds a 40% surge of top-up questions (10 Banking77 top-up intents), which the knowledge base does not cover.

PSI bands: < 0.10 stable · 0.10-0.25 moderate · > 0.25 significant. KS p-values are asymptotic.

## How the monitor changed after meeting real traffic

The first version monitored retrieval confidence, query length, answered topic and behavioural rates only. On these same windows it would report the top-up surge as **OK** (confidence PSI 0.085, topic-mix PSI 0.070, abstention 69.2% -> 74.0%). Real phrasing is refused so often that one kind of unanswered question looks like another.

Two changes followed, both made after seeing results on this simulated traffic, so the repeated-seed check above is the fair measure of how the monitor behaves:
1. A `query_terms` feature: PSI over the content terms of the PII-masked queries.
2. Each query now counts once in that feature. When every term occurrence counted, one long jailbreak prompt in the baseline window (about 1% of all terms) pushed every control window to WATCH. The repeated check also draws a fresh baseline each time.

## Reading the result

- 220 of 500 drifted-window requests were surge (top-up) questions. The pipeline abstained on 171 (78%) of them, which pushes the abstention rate up.
- It **answered the other 49** from the nearest covered section (credit-card: 22, fees-and-charges: 20, savings-account: 6). Those answers cite real policy text about a different product. Drift monitoring is the production safety net for out-of-scope questions that the abstain threshold lets through.
- Recommended response: route top-up intents to a human or a static 'not available in this channel' reply, and check whether a top-up policy is missing from the knowledge base. Re-run the quality gate after any document change.
